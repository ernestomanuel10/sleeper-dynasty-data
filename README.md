## Data directory — what to read

Replace `YEAR` with `2025` or `2026`.

| Question / purpose | Repository file | Interpretation |
|---|---|---|
| League status, season, settings, playoff format | `data/YEAR/league.json` | Source of truth for league settings |
| Manager names, user IDs, team names | `data/YEAR/users.json` | Match `user_id` to roster `owner_id`; team names may change |
| Team roster IDs, players, starters, roster settings | `data/YEAR/rosters.json` | `roster_id` is the key used by matchups |
| Regular-season W/L, points for/against | `data/YEAR/standings.json` | Computed from Sleeper roster settings, NOT final playoff placements |
| All weekly matchup roster entries | `data/YEAR/matchups.json` | Each row has a `week`, `matchup_id`, `roster_id`, `points`, `starters`, `starters_points`, `players_points` |
| One week's matchups | `data/YEAR/matchups/week_01.json` through `week_18.json` | Pair entries with the same non-null `matchup_id` **within the same week**; a null matchup ID is not an ordinary paired matchup |
| All weekly transactions | `data/YEAR/transactions.json` | Filter `type === "trade"` for trades; includes other transaction types |
| One week's transactions | `data/YEAR/transactions/week_01.json` through `week_18.json` | Includes trades, waiver claims and free-agent moves |
| Traded future draft picks | `data/YEAR/traded_picks.json` | Pick ownership; not a complete historical trade log |
| Winners playoff bracket | `data/YEAR/winners_bracket.json` | `r` round, `w` winning roster ID, `l` losing roster ID, `p` placement (1 champion, 3 third-place game, etc.) |
| Consolation bracket | `data/YEAR/losers_bracket.json` | Losers/consolation results |
| Draft IDs | `data/YEAR/drafts.json` | Lists drafts; **does not contain full draft picks** |

All files are generated by [fetch_sleeper.py](fetch_sleeper.py). The current script fetches league, users, rosters, picks, brackets, drafts, and weeks 1–18 matchups and transactions for **both** seasons. It does **not** currently save complete individual draft pick selections, NFL player metadata, injury updates, or an explicit refresh timestamp. To resolve Sleeper numeric player IDs to names, consult a verified player-ID mapping; never guess.

### Essential matchup analysis procedure

1. Read `users.json` and `rosters.json`; build `roster_id → owner_id → display_name` mapping. For every current-season graphic, use `metadata.team_name` **only when present and nonblank**; otherwise use the exact `display_name`. Never substitute a nickname, historical alias, manager's first name, or invented team name. Preserve the username and user ID for identity matching.
2. Read `league.json` to determine regular season versus playoffs, and `matchups.json` or specific week files.
3. Group matchup entries by **both week and non-null matchup_id**. A head-to-head matchup normally has exactly two entries. Compare `points`; calculate margin and combined score.
4. For **highest-scoring matchup**, rank the sum of both teams' points. For **closest game**, rank the absolute difference. For **biggest blowout**, rank the difference descending. Clearly state whether analysis includes playoffs.
5. For player-level weekly scoring, join `starters` with `starters_points` by array position, or use `players_points`. Player IDs are not names.
6. For playoff placements, consult `winners_bracket.json`, **not** the regular-season standings order. In a multi-week playoff final, inspect each scoring week and explain whether the championship total is one week or an aggregate.
7. For trades, filter `transactions.json` by `type: "trade"`, examine roster IDs, adds/drops and draft picks, and identify managers through the roster/user mapping. Avoid confusing pick transfers with trades.
